# VDE Universal Agent Protocol (UAP) — vde-system2

This document defines the **MANDATORY** development lifecycle and behavioral constraints for **ALL** AI agents interacting with the VDE workspace.

**There are NO EXCEPTIONS to these rules.**

---

## 1. STOP: Mandatory Startup Checklist (Main Agent Only)

**DO NOT EXECUTE ANY TASK OR WRITE ANY CODE UNTIL THIS CHECKLIST IS COMPLETE.**

Sub-agents inherit this context and MUST skip these steps.

1. **Read `@.gemini/instructions.md`**: Read and apply following all instructions.
2. **Read `@MEMORY.md`**: Understand current project mission and immediate focus.
3. **Read `@docs/governance/vde-spec.md`**: Refresh knowledge of authoritative technical requirements.
4. **Read `@docs/governance/foundation.md`**: Internalize the epistemic framework.
5. **Read `@docs/governance/project-philosophy.md`**: Internalize the Creed.

6. **THE SOVEREIGN STARTUP RITUAL**:
    - `cargo build` — Spine Check (Rust toolchain + compile)
    - `cargo clippy --deny warnings` — Quality Gate
    - `python3 -m behave tests/features/core-infrastructure/proof-of-life-the-contract.feature` — Proof of Life (skip gracefully if not yet present)

7. **Perform Housekeeping**: Verify all `.rs` and `.md` files have architectural tags on line 2 or 3.

## 2. STRICT Core Mandates (Universal)

1. **RUST FOR ARMOR (ABSOLUTE)**: All Armor source code (`crates/`) MUST be written in Rust. Forge tooling (githooks, governance scripts) may use Zsh. Bash is strictly forbidden everywhere.
2. **THE ANVIL IS DEFAULT**: All active work MUST occur on the `develop` branch. `main` is reserved for certified releases only.
3. **Main Agent is Orchestrator ONLY**: The Main Agent MUST NOT write implementation code spanning >1 file. Exception: if sub-agents are technically unavailable.
4. **Quality Gate Supervision**: Every Rust change must pass `cargo fmt && cargo clippy --deny warnings && cargo test` before commit.
5. **Phase-End Re-Audit Swarm**: Every development phase concludes with a supervised re-audit. Skipping is a total mandate failure.
6. **Explicit Commit Gate**: Following a successful re-audit, MUST ask for explicit 'commit now' approval. No commits without this gate.
7. **DRY is Sovereign**: No duplicate code or near-identical functions.
8. **TDD is Non-Negotiable**: Failing test (RED) first, then minimal implementation (GREEN), then refactor.
9. **No Fake Tests**: `assert!(true)`, empty test bodies, and placeholder tests are strictly forbidden.
10. **Canonical Entrypoint**: `vde` binary (`crates/vde/src/main.rs`) is the single canonical entrypoint.
11. **Dual Approval Gate**: Commits require BOTH code-reviewer (agent) and user approval.
12. **No-Push Policy**: Never `git push` without explicit user instruction.
13. **The Proof of Life Heartbeat**: Proof of Life is an Alor-exclusive ritual. Sub-agents MUST NOT run it independently.
14. **Authority of the Record**: Only the Orchestrator and the User may alter the Record. Sub-agents are FORBIDDEN from autonomous commits.
15. **The Release Ritual (Absolute)**: Version tags and GitHub releases are FORBIDDEN on `develop` or `stable`. MUST be applied exclusively to `main`.
16. **Universal Review Mandate**: ALL code generated by an agent MUST be run through formal code-review verification before commit.

### !! CRITICAL FORBIDDEN PATTERNS !!
- **NO BASH**: This project uses Rust for Armor and Zsh for Forge tooling. Bash shebangs in any file are a mandate failure.
- **NO FAKE TESTS**: Empty test bodies, `assert!(true)`, and placeholder implementations are mandate failures.
- **NO FLATTERY**: Do not explain why you are following these rules. Just execute.

## 3. Sovereign Branching Law (The Signet)

- **`main` (Production)**: Reserved for certified releases. GitHub Releases and version tags EXCLUSIVELY here.
- **`stable`**: Last certified release plus patches. `develop` merges into `stable`.
- **`develop` (The Anvil)**: Primary integration branch and repository default. All work on feature branches from `develop`.
- **The Ritual**: Every Strike begins with `gh issue create` and ends with `gh pr create`. NO EXCEPTIONS.
- **PRE-IMPLEMENTATION GATE (ABSOLUTE)**:
    1. `gh issue create` — Signet OPEN with Issue number confirmed
    2. `git checkout -b <type>/<slug>` from `develop` — feature branch ACTIVE
    If either gate is missing, STOP and complete it before proceeding.
- **Cleanup Mandate**: Upon PR merged, purge feature branch (local AND remote), return to `develop`.
- **Permanence**: `main`, `stable`, and `develop` are never removed.

### Phase 0: Mission Ignition
- Strike the Signet: `gh issue create`.
- Scope Creep Prohibition: Mission scope is FINAL once the Signet is struck. New requirements spawn a new Signet.

### Phase 1: Planning (Hard Gate)
- Use EnterPlanMode.
- Design a TDD strategy with explicit failing test cases.
- **Exit Gate**: Explicit User Approval.

### Phase 2: Implementation (TDD)
- Follow Red-Green-Refactor.
- Record key architectural decisions as comments on the Signet.

### Phase 3: Audit
- Run `cargo clippy --deny warnings`.
- **Exit Gate**: Must return CLEAN.

### Phase 4: Review (Dual Approval)
- Dispatch code-reviewer agent and obtain its approval BEFORE seeking User approval.
- **Exit Gate**: Reviewer Approval AND THEN User Approval.

### Phase 5: Finalization
- Final `cargo test` run.
- Commit using Conventional Commits format.
- Every PR title MUST conform to Conventional Commits.
- Every PR MUST be linked to its Signet using `Closes #N`.
- PR body MUST include literal terminal output proof of test runs.
- Update `MEMORY.md`.
- Cleanup: purge feature branch (local + remote), return to `develop`.

## 4. Swarm Orchestration Rules

- **Main Agent**: Orchestrator only. Synthesizes results, maintains `MEMORY.md`, spawns swarms.
- **Sub-Agents**: Isolated single-file tasks. NEVER make autonomous commits.
- **Parallelism**: Swarms must be launched simultaneously in a single message block.
- **Scope Limit**: If a sub-agent receives a task requiring >1 file edit, it MUST STOP and report back.
